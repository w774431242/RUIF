### 实现期踩坑与经验（可复用）

1. **`Source/Core/AssemblyInfo.cs` 是版本第三处落点** —— 除 `Api.VersionString` 与 `About.xml` 外，`AssemblyVersion` / `AssemblyFileVersion` / `AssemblyInformationalVersion` **也要同步**（实现方只提了前两处，主理人核对时才发现）。
2. **验版本字符串必须用反编译，不能用字节 grep** —— .NET 的**字面量字符串存在 `#US` 堆、是 UTF-16**；按 UTF-8 搜会得**假阴性**（我据此误判过一次"版本没进 dll"）。属性 blob（如 `AssemblyVersion`）才是 UTF-8。
3. **`verify_release.ps1` 在 Windows PowerShell 5.1 下会假 FAIL** —— 5 处 `Get-Content -Raw` 缺 `-Encoding`，5.1 默认 ANSI/GBK 读取 ⇒ 吞掉 UTF-8 中文注释里的 `<` ⇒ 第 4 道 XML 解析假失败。**工件良构、属工具缺陷**；已修（双口径验证）。
4. **"注释里的错事实"会跨文件扩散** —— 界面部反编译发现方案里"`label` 为 `null` 时回退 `Tr.Get(key)`"这一机制**根本不存在**，而该错误已扩散到**方案 §5.8 + 验证台注记 + 两个语言文件的 XML 注释**三处。**注释错误比代码错误更危险**（维护者会照着改）。
5. **禁用件的隐藏代价**：`ButtonInvisible`「总是调用 + 事后 AND」保住了 control-ID 序（不丢点击），但禁用件**仍占用 id 并可能成为 `hotControl`**（调用方不可观测）。
6. **`GUI.GetNameOfFocusedControl()` 返回 string、可能每帧分配** ⇒ 只在 `controlName != null` 的 opt-in 路径调用；`focusRing` 视觉通路独立可用。
7. **团队成员的 shell 环境可能损坏**：界面部侧 Bash/PowerShell **stdout/stderr 恒空 + exit 0**（命令实际执行），它的绕法是"**重定向到文件再 Read**" —— 与主理人侧 PowerShell 的已知行为一致，值得作为通用 fallback。
8. **一次消息里发两个 Edit 调用只有最后一个生效**（界面部踩 2 次）⇒ 规范：**一次一个 Edit、改完即 Read 验**。
