## 3. 性能专项

### 3.1 装饰层每帧绘制成本模型（v2.2.0 新增能力的预算）

`DrawDecor` 的所有重复图案都有**硬上限**（上限 = 每帧绘制预算）：

| 维度 | 上限常量 | 值 |
|---|---|---|
| 渐层行数 | `MaxGradientRows` | 48 |
| 形状遮罩行数 | `MaxShapeRows` | 56 |
| 扫描线 | `MaxScanlines` | 64 |
| 网格线/轴 | `MaxGridLines` | 44 |
| 点阵总数 | `MaxDotsTotal` | 220 |
| 斜纹条数 | `MaxHazardStripes` | 40 |

**最坏单面板**（最花哨档：`GradientDown` + `Neon` + `Scanlines` + `Flow` + `CornerTicks`）：

```text
渐层 ≤48 + 扫描线 ≤64 + 霓虹外扩(3层×4边) ≤12 + 主描边 ≤4 + 流光(2段×4边) ≤8 + 四角标记 ≤8
= 约 144 quads / 面板 / 帧
```

**设置页画廊**（12 张 `Card` 档：渐层 + 边框 + 角标，无纹样）≈ **720 quads/帧**（渐层占主体）。

> 结论：量级合理（IMGUI 下同屏数百 quad 属常态，且仅设置页打开时存在），**不构成违规**；但它是本轮唯一"接近预算上限"的新增绘制面，因此把上限本身纳入体检（见 §4 第 8 组）。

### 3.2 绘制路径翻译（关键修复）

| 位置 | 修复前 | 修复后 |
|---|---|---|
| 组件层 62 处 | 已经 `Tr`（有界缓存） | 不变 |
| **设置页 + 主题画廊 15 处** | **直接 `.Translate()`**：每帧 15 次引擎字典查找；画廊 12 张卡的显示名也在其中 | 全部经 `Tr`：命中即 **0 查找 0 分配**，语言切换自动失效 |

量化：设置页打开时每帧翻译查找 **约 25 次 → 0 次**（缓存命中）；同时消除了"框架自身不守自家纪律"的架构不一致。

### 3.3 分配纪律

绘制路径**零堆分配**（全部 struct 参数，循环内不 `new`）；组件层容器分配 7 处经人工确认**全在点击分支或惰性初始化**（第 6 组体检）。
