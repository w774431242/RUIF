## 4. 修复明细

### 4.1 绘制路径翻译有界缓存（PERF-001 / PERF-002）

新增 `Source/Core/TrCache.cs`，`Core/Tr.cs` 接线：

| 要素 | 实现 |
|---|---|
| 来源 | 构造时注入的 factory 委托（唯一权威仍是 `LanguageDatabase`，缓存只加速） |
| 失效 | 语言戳（`LanguageDatabase.activeLanguage`）**引用变化**即整体清空 → 语言切换不会残留旧语言 |
| 上限 | 512 条；满则清空重建（**绝不无界增长**，符合 AI-004） |
| 不缓存 null | 避免"翻译环境暂缺"被固化成永久空白 |

**关键设计（省下 21 处调用点的改动）**：新增重载 `Tr.Get(string, int)` —— 重载决议中**精确匹配优于用户定义隐式转换**，因此原本传 `int` 的调用点自动改走缓存版，一行调用代码都不用动。float/string 实参仍走 `NamedArgument` 重载。

**刻意不缓存 float/string 参数**：复合键必须拼接（拼接本身即一次分配），与省下的 `Formatted` 分配净收益相当 —— 该取舍写进 `TrCache` 注释，避免"为指标而优化"。

**可测性**：`TrCache` 不引用 UnityEngine/Verse（语言戳与取值均委托注入），新增 9 个离线单测覆盖：命中返回同一实例 / int 键命中 / (键,值) 隔离 / Ordinal 键 / 语言戳变化失效 / 容量有界 / null 不缓存 / 构造参数校验 / 语言戳委托缺失容错。

### 4.2 设置页去每帧分配（PERF-002）

| 方法 | 原问题 | 修法 |
|---|---|---|
| `RUIFSettings.SourceSummary()` | 每帧字符串拼接（设置页开着就每帧分配） | 惰性缓存 + `ApplyFromDefs` 时失效 |
| `RUIFMod.DevDocsPath()` | 每帧 `LoadedModManager.GetMod` 查找 + `Path.Combine` 分配 | 惰性缓存；**失败结果同样缓存**，避免每帧重复写警告 |

### 4.3 设置页文案 Keyed 化（GOV-010 / LOC-002）

| 位置 | 修复前 | 修复后 |
|---|---|---|
| `SettingsCategory()` | `"RUI Framework"`（英文硬编码，玩家可见） | `"RUIF.Settings.Category".Translate()` |
| XML 来源行 | 直接拼接 `SourceSummary()` 的英文诊断串 | `RUIF.Settings.Source.None` / `.Def`（{0}=DefName、{1}=themeId、{2}=主题数） |

中英各 +3 键（8 → 11，合计 71）。`SourceSummary()` 保留为**纯函数**（离线可测、供日志与开发者用），其英文输出登记为 EXC-003。

### 4.4 门禁升级（九道 → 十道）

- 检查 5 扫描前**剔除注释**（此前 `Tr.cs` 文档注释里 `Tr.Get("K", 3)` 的示例被当成真实键 → 假"缺翻译"）
- **新增检查 10**：同键中英**占位符集合一致性**（LOC-004）+ **文件内重复键**（LOC-005 —— XML 重复键不报错、后者静默覆盖前者，是"翻译改了却不生效"的经典坑）

### 4.5 文档与测试补齐

- README 全量对齐 v2.1.1（版本 / 单测 186 / API 79·478 / 门禁十道 / 新报告 / EXC-003）
- 新增 `Tests/SettingsDataTests.cs`（4 用例）锁定三个设置数据类的默认值与契约 → 静态体检"零测试引用的公开类型"由 9 → **6**（余下 6 个是纯绘制类，离线环境无法实例化，见 §7.2）

### 7.1 遗留：XML 注释覆盖 67.5%（P2）
138 个公开成员缺 XML 注释（IDE 悬停空白）。**不阻断发布**（`GenerateDocumentationFile` 已开，`CS1591` 有意静音）。建议按类型分批补齐，优先 `Api` / `Theme` / `Layout` 这类第三方最常直接调用的门面。

### 7.2 遗留：6 个绘制类无测试引用（已定性，不构成缺陷）
`FeedbackAtoms` / `FeedbackAtomsB` / `OfficialDataAtoms`(B/C) / `TextAtoms` —— 均为即时模式绘制类，**离线环境无法实例化**（需 Unity IMGUI 上下文）。框架对这类组件的既有策略是：**把可测逻辑拆进 `*Fmt` 纯函数**（已有 `FeedbackFmt` / `OfficialFmt` / `NavFmt` / `TextFmt` 等测试覆盖）。经核对，这 6 个类的可测部分均已由对应 `*Fmt` 测试覆盖。

### 7.3 NOT RUN（沙箱无法起游戏进程，逐项如实登记）
1. 实机启动：Player.log 出现 `[RUIF] v2.1.1 loaded.` 与 `settings applied: theme=…`；
2. 设置页：分类名/来源行显示、主题切换生效（本次改动的直接验收点）；
3. **绘制路径缓存的实机验证**：切换语言后界面文案立即跟随（缓存失效生效）、切回后无残留旧语言；
4. 长文案截断：`DataExAtoms`(56f) / `FeedbackAtoms`(70f) 固定宽度在英文/中文下的实际表现（静态无字体度量，无法结论）；
5. 禁 RUIF 时 `RUIF.Sample` 的软依赖降级路径。
