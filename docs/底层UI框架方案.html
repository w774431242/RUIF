1 · 定位与目标

RUIF 是一个通用的、面向所有 RimWorld Mod 开发者的 UI 框架：以独立框架 Mod 形态分发（与 Harmony / HugsLib 同模式），任何 Mod 引用 RUIF.dll 即可获得统一组件、声明式布局、主题系统与调试工具——让 Mod 作者只声明「要什么组件、什么数据」，不再手写 Rect 布局数学与 GUI.color 配对。

明确边界：这是 RimWorld IMGUI 组件框架，不是 Web 组件库。技术栈是 C# + Verse/Unity GUI，无法与 React/Vue 互通。它的「开发者」是全体 Mod 作者——框架零业务依赖，不绑定任何业务 Mod（包括 PersonalChronicle）。
与 PersonalChronicle 的关系：PC 不再是框架的宿主，而是首个消费者 + 参考实现。RUIF 的令牌与组件设计从 PC 档案馆 UI 实战沉淀泛化而来，但公共 API 一律 RUIF.*、默认主题为通用风格；PC 侧迁移是路线图 I4 的可选收口，而非框架前提。

设计目标

  • 零业务依赖：不依赖 PersonalChronicle 或任何业务 Mod；数据由调用方注入，框架不读游戏状态。
  • 声明式布局：窗口提供内容，框架算坐标（解决每窗口手写 rect.y += h 的重复劳动）。
  • 绘制态零泄漏：任何组件内部 GUI.color / GUI.enabled 修改必须配对恢复，调用方无需关心。
  • 令牌单一真源：颜色/间距/字号只来自 RUIF.Theme，窗口内禁止 new Color。
  • 可主题化 + 可扩展：运行时换肤；第三方 Mod 可注册调色板与自定义组件。
  • 稳定公共 API：面向第三方即「API 即承诺」——SemVer、Adapter 隔离版本、弃用走过渡期。
  • 可测试边界：布局/令牌层与 Verse GUI 静态解耦，便于单测。

2 · 设计来源与参考实现

RUIF 不依赖、不引用 PersonalChronicle；但其令牌与组件设计从 PC 档案馆 UI 的两层 Design System 实战沉淀泛化而来——那是约 30 个组件、3 套主题、~120 调用点、多轮实机验收过的参考实现。下表盘点参考实现已验证可直接泛化的能力，与 RUIF 需原生新建的框架能力：

参考实现单元已验证能力（泛化进 RUIF）RUIF 需原生补齐（框架能力）
UITheme 颜色/间距/字号/度量令牌；3 套调色板；状态色解析；CJK 行高 22f 经验值 注册式调色板 + 组件语义令牌 + 通用默认主题（贴合原版风）；公共类型定名 RUIF.Theme
ArchiveUiStyle 兼容转发壳（过渡产物，非能力） 不设历史包袱：公共 API 一次定型，靠 Adapter 应对游戏版本演化
UIComponents（15 组件） Label / ShadowLabel / Panel / Card / PairCard / SectionTitle / Rule / Border / Pill / Badge / ClickableCard / TintedBox / ProgressBar / TruncateToWidth 的绘制与交互卡模式 签名泛化（剥离 PC 业务语义如 FactionCodex）；坐标改由 L4 编排
KpiGrid / Sidebar / Tables 六宫格 KPI、侧栏导航、表头 / 斑马纹 / 空状态 参数化（Grid(cols)）、通用 Table 抽象、统一 Selection 模型

核心缺口一句话：参考实现有「画什么」的组件，没有「放哪、怎么交互、怎么组合」的框架，也没有面向第三方的版本 / 分发 / 扩展机制——这正是 RUIF 要补全的 L0/L4/L5 + 集成层（§10）。

3 · 分层架构

从下到上 5 层，单向依赖（上层可依赖下层，禁止反向）。参考实现覆盖 L1–L3 的大部分经验；RUIF 五层全部自建——L0/L4/L5 纯新建，L1–L3 在参考实现基础上泛化。

L0 运行时适配
GUI 安全封装：Draw.Scope（GUI.color/enabled 栈式保存恢复）、裁剪、滚动视图、坐标换算。所有绘制最终经此层，杜绝泄漏。
L1 设计令牌
UITheme（升级）：注册式调色板、组件语义令牌（button/card/tag）、间距/字号/度量常量、状态色解析器。无绘制、无状态读取。
L2 绘制原语
Primitives：Box / Text / Divider / Texture / Rule。纯几何，1 个 Rect 入参，经 L0 画。
L3 复合组件
Controls：Button / Card / Tag / Badge / ProgressBar / KpiCell / Table / Sidebar。组合 L2，携带轻量视觉状态（hover），不含业务交互。
L4 布局编排
Layout：Stack(V/H) / Grid / Section / ScrollView / Spacer。输入「内容+约束」，输出各子项 Rect，窗口不再手写坐标。
L5 交互行为
Behavior：Selection 模型、Command（点击→回调）、Hover/Active 视觉态、键盘导航、与调用方状态/数据绑定（框架不关心数据来源）。窗口只 Bind(data)。

4 · 各层设计

L0 · 运行时适配层 新增

所有 GUI.* 副作用集中在此，提供栈式作用域，保证「改了必恢复」：

// 调用方永远不必配对 finally
using (Draw.Color(accent))        // 压栈旧色，退出恢复
using (Draw.Enabled(false))       // 禁用态
using (Draw.Clip(rect))           // 裁剪区域
{
    Widgets.DrawBoxSolid(rect, color);
}

// 滚动视图：返回视口 + 自动处理 scrollPosition
Rect view = Layout.Scroll(outer, contentSize, ref scroll);
参考实现里每个组件都手写「try{ GUI.color=.. }finally{ GUI.color=prev }」配对样板——正是 L0 要统一收编、让组件作者彻底摆脱的重复劳动。
L0 必须内建的 RimWorld 1.6 约束（吸收自 RUI 评估：一个 RW UI 框架若不包住这些坑，组件作者每行都在踩雷）：
  • Listing_Standard.RadioButton(string,bool) 返回 bool，不能 ref；1.6 无 RadioButtonGroup，单选组须自己循环。
  • Widgets.ButtonText 无 disabled 参数——禁用用 active:false。
  • GUI.color 修改必须配对恢复，否则染色泄漏到后续所有控件（全游戏范围）。
  • TipSignal 第二参是延迟秒数，不是开关。
  • CJK 行高经验值 22f（UITheme.FontBodyLineHeight），不能套 Web 字体度量。
  • 1.6 Widgets.DrawBoxSolid 内部会重置 GUI.color 为传入色——想画半透明 tint 必须直接传 tint 色（TintedBox 踩过的坑）。

L1 · 设计令牌（公共类型 RUIF.Theme）

  • 注册式调色板：RUIF.Theme.Register("myTheme", palette)；内置 Vanilla（贴合原版风，默认）与 Dark 两个通用主题，Epic/Gothic/Steampunk 作为示例主题随源码提供（示范第三方如何注入皮肤）。
  • 组件语义令牌：按组件拆色（Button.Bg/Hover/Text、Card.Bg/Border/Accent），由调色板派生，调用方不猜色。
  • 间距/字号/度量：SpaceXs..Lg、FontBodyLineHeight=22f 等常量（CJK 行高经验值已在参考实现验证）。
  • 通用状态解析：StateColor(positive,negative) 内置；业务专属色解析（职称/勋章/事件分类等）属于消费 Mod，经解析器扩展点注册而非内置。

L2 · 绘制原语 参考实现泛化

Panel / Card / Rule / Border / Pill / Badge 等下沉为无状态的 L2 原语，签名统一 (Rect, ...token)，内部只调 L0。

L3 · 复合组件（Controls）

在参考实现组件基础上补两类：

  • 有交互的 Control：Button(rect, label).OnClick(action) 内部用 L5 的 Command，调用方不再手写 if-click 判断。
  • 参数化复合：Grid(cols).Add(cell) 取代固定格数的专用网格；Table 抽象为通用组件，参考实现的 TableHeader/ZebraRow/EmptyState 成为其特例。

L4 · 布局编排 新增 · 最关键

// 窗口不再算坐标，只声明结构
var root = Layout.VStack(outer, gap: SpaceSm);
root.Add(Section("概览", () => {
    Layout.HStack().Add(kpi1).Add(kpi2).Add(kpi3);
}));
root.Add(Layout.Grid(cols: 2, rowH: 110f)
    .Add(cardA).Add(cardB).Add(cardC));
root.Add(ScrollView(content, ref scroll));
root.Build();   // 计算所有 Rect 并绘制
收益：消除每个窗口里重复的 rect.y += height + gap 布局循环，且天然支持封装行高契约（大卡≥110f / 正文行 22f 等，CJK 安全值已在参考实现验证）。

L5 · 交互行为 新增

  • Selection：Selection<T> 模型，侧栏/列表从「返回 bool」升级为绑定选中项。
  • Command：点击/回车归一为 ICommand，组件注册回调，窗口只关心语义动作。
  • 数据绑定：组件 .Bind(data) 接收调用方注入的纯数据/快照；框架不读游戏状态、不做业务聚合（排序与 null-guard 归调用方）。
  • 键盘导航：容器内 Tab/方向键焦点环，为 a11y 打底。

5 · 主题系统

  • 运行时换肤：RUIF.Theme.Apply(id)——先查注册表，未注册回退默认主题（fail-safe：坏配置不 brick UI）。
  • 持久化归消费 Mod：框架只提供 Apply(id) 与当前主题查询；主题选择存进哪个 Mod 的 Settings 由消费方决定。
  • 第三方注册：暴露 RUIF.Theme.Register 与 Palette.Builder，任意 Mod 可注入调色板，RUIF 不独占皮肤。
  • 纹理主题：1.6 贴图在 asset bundle，只能 XML 乘法染色——L0 资源层提供 Texture.ForToken(id) 统一取色，避免散落硬编码色值；贴图缺失一律回退令牌色。

约定规则示例

7 · 三档 API 设计标准 吸收自 RUI

档位目标示例特点
Minimal 最小5 秒能用RUIF.Button("开始")默认主题/尺寸、最少参数
Advanced 进阶正式 Mod UIRUIF.Button(...).Style(...).Tip(...)组合属性、事件、绑定
Expert 高阶复杂系统RUIF.Table(...).Virtualized().MultiSelect()状态、数据源、虚拟化、扩展点
同一组件向上兼容：Minimal 是 Advanced 的默认值特例，Advanced 是 Expert 的默认配置特例。禁止「简单用法要先学一堆参数」——这是组件库 DX 的第一道门槛。

8 · 兼容性适配层 吸收自 RUI

把 Verse / Unity API 收进 Adapter，不泄漏到公共 API；未来游戏版本改 API 时只动 Adapter，不动任何组件。

RUIF 公共 API
   │
   ▼
RUIF.Internal
   │
   ▼
RimWorld 1.6 Adapter
   ├── Verse.Widgets
   ├── WindowStack
   ├── Tooltip / TipSignal
   ├── GUI / UnityEngine
   └── RimWorld-specific helpers
与 L0 运行时适配层是同一件事的两面：L0 负责「安全封装」，Adapter 负责「版本隔离」。组件层永远看不到 Widgets.*。

10 · 集成与分发（面向 Mod 开发者）

接入模式：框架 Mod（与 Harmony / HugsLib 同模式）

RimWorld 会加载所有已启用 Mod 的程序集，因此 RUIF 以独立框架 Mod 分发，全游戏只加载一份 RUIF.dll；消费 Mod 只引用、不内嵌，从根上避免「多 Mod 各带一份不同版本 dll」的经典冲突。

  • 消费 Mod 声明依赖：About.xml 写 modDependencies + loadAfter（packageId PersonalChronicle.RUIFramework）；csproj 引用 RUIF.dll 但发布包内不携带该 dll。
  • 版本探测与降级：RUIF 提供 RUIF.Version 常量与运行时探测；消费 Mod 做最低版本断言——低版本环境给出可读提示或功能降级，而不是炸 null。
  • SemVer + 弃用过渡：主版本内公共 API 冻结；删改 API 先 [Obsolete] 保留一个主版本，并在 changelog 标注迁移路径。

扩展点（第三方可注册，RUIF 不独占）

  • 主题注册：RUIF.Theme.Register(id, palette)——任意 Mod 注入调色板。
  • 组件注册：自定义 Control 注册进 Gallery，自动获得游戏内预览与三档文档位。
  • 语义解析扩展：业务语义色（稀有度 / 品质 / 阵营等）经解析器扩展点挂接，框架只内置通用解析。

本地化与分发

  • 本地化：框架内置文案走 Keyed（RUIF.UI.*）；组件 API 一律收已翻译字符串，不替消费 Mod 做翻译决策。
  • 分发：Steam Workshop（框架 Mod 本体）+ GitHub Release（dll + 离线文档）+ 本地引用开发模式；发布区路径 TBD，启用前按「两区同步 + 哈希校验」约定执行。
  • 冲突面控制：核心框架不打 Harmony 补丁（如确需，拆独立可选模块），把与其他 Mod 的冲突面压到最低。

11 · 落地路线图

迭代范围交付兼容策略
I1 框架骨架 独立 Mod 工程（RUIF.Core.dll）+ L0 运行时适配 + L4 布局骨架 Draw.Scope、Layout.VStack/HStack/Grid/ScrollView、Vanilla 默认主题令牌 新工程零历史包袱；PersonalChronicle 不动
I2 组件层 L1 语义令牌 + L2/L3 组件（参考实现泛化） Button/Card/Pill/Badge/ProgressBar/Table/Sidebar 等公共组件 + 三档 API 形态 API 未冻结，可随早期反馈调整；变更必记 changelog
I3 主题/交互/DevTools 注册式主题 + L5 行为 + 游戏内 Gallery Theme.Register、Selection/Command、键盘导航、组件 Gallery 第三方可开始注册主题与自定义组件
I4 发布收口 API 冻结候选 + Workshop/GitHub 发布 + 接入文档 示例消费 Mod、版本探测、SemVer 承诺生效 首个消费者接入：PersonalChronicle 迁移（可选，另行排期 + 全量回归）
建议从 I1 起步：L0/L4 纯新建、不触碰任何现有代码，风险最低、收益（消除布局样板）立竿见影。每迭代保持「编译 0 错 0 警 + 单测通过」闸门。

12 · 工程化与验收

  • 编译：独立 csproj（net48 / x64，按需引用 Assembly-CSharp / Verse / UnityEngine / 0Harmony），0 错 0 警；与 PersonalChronicle 工程互不依赖。
  • 单测：布局层（L4）与令牌层（L1）与 Verse GUI 解耦，可用 NUnit 测坐标计算与令牌解析；交互层用模拟事件。
  • 文档：每个 Control 配「签名 + 参数 + 示例 + 截图/示意」，沉淀到 RUIF/docs/；对外 API 变更必记 changelog（面向第三方）。
  • 契约回归：换肤后全组件回归——无 new Color 残留（grep 红线）、无绘制态泄漏、贴图缺失回退正常。
  • 红线闸门：AI 工具只进开发流；框架不读游戏状态（数据由调用方注入）。

13 · 红线（重申）

  • 零业务依赖：框架不引用任何业务 Mod；组件内绝不读 pawn/map/stat、不做业务聚合——数据由调用方注入。
  • 公共 API 即承诺：RUIF.* 不泄漏 Verse/Unity 类型；SemVer + [Obsolete] 过渡；未冻结前变更必记 changelog。
  • 单一程序集：消费 Mod 只引用、不内嵌 RUIF.dll；核心框架不打 Harmony 补丁（可选模块除外）。
  • 窗口内禁止裸 GUI.color 与 new Color；一切经 L0/L1。
  • 所有 AI 工具只进开发流，不进 Mod 运行时（沿用工程铁律）。
  • 设计期不进任何发布区；RUIF 发布区路径 TBD，启用后按两区同步 + 哈希校验约定执行。
