# RUIF 工业管理方向扩展设计提案（2026-09-09 22:30）

> 问题：现有 46 件组件（42 原子 + Charts 10 件 + 导航 12 等）之外，是否还有**官方支持可落实**的额外设计——统计、可视化、数字孪生等工业管理方向。
> 方法：对 `Assembly-CSharp.dll`（1.6，15.7 MB）做字节级类名核验（不臆造 API 名）+ RUIF 范式约束推演。

## 一、结论摘要

**有，且空间比图表图鉴估算的更大。** 图表图鉴（48 项）只论证了"表达层"；本次实证确认官方还有一整层**公开数据面**（能源/生产/物料/空间/人/宏观六大域）足以支撑工业管理级应用。表达组件增量不多（约 15 项），真正的增量是**数据桥（DataBridge）子系统**——这是图鉴时代没算进去的新账。

## 四、唯一需要新建的子系统：DataBridge（数据桥）

工业方向与图表方向的本质差异：**图表图鉴只画数（数据由调用方给），孪生要取数（数据在游戏世界）**。据此新增一个独立子系统，分层置于 UI 之下：

```
DataBridge（采样/缓存/快照） → *Fmt（域数据→视图模型） → Charts/Atoms（绘制）
```

设计要点（与 PersonalChronicle 活读/快照双轨经验一致）：
1. **低频采样**：按域分档（能源/库存 1–2s，地图格网 5–10s），滚动环形缓冲，绝不每帧活读 map cells；
2. **快照不可变**：UI 组件只读快照视图模型，采样在后台节奏完成——即时代码零分配纪律不被破坏；
3. **域驱动**：PowerDomain / StockDomain / MapDomain 各自独立注册，Mod 消费方按需挂 MapComponent；
4. **纯 C# 可测**：采样聚合逻辑不碰 UnityEngine，进现有 NUnit 测试链。

## 五、过滤项（官方/范式无法支撑，不评估）

| 项 | 原因 |
|---|---|
| 像素级地形贴图孪生 | `TerrainDef.texture` 虽公开，但贴图绘制违背 RUIF 零贴图纪律，且原版俯视相机已覆盖该需求；如确需属特例讨论 |
| WebGL / 3D / 实时高频流 | 同图表图鉴过滤清单（引擎与范式双重不支持） |
| 多地图并发孪生 | 1.6 同屏仅一张活动地图，数据面天然单图 |

## 六、落地顺序建议

1. **第一批（≈3 人日）**：T1 四原子（Gauge/LEDMatrix/BottleneckRibbon/MachineStateTimeline）+ T0 拼装三件——表达层补齐，DataBridge 未动，历史趋势板先用手动数据。
2. **第二批（≈5 人日）**：DataBridge v1（PowerDomain + StockDomain 两域）→ 历史趋势板、库存水位板接真数据。
3. **第三批（≈6 人日）**：MapDomain + GridMap 俯视格网 + CircuitTopology（T2 复合件）。
4. SPC/Pareto 与 Sankey 随 Charts 子系统批次（图鉴 v1.2 口径）。

> 合计新增 ≈15 项设计 + 1 个子系统，表达组件零范式冲突；风险集中在 DataBridge 的采样节奏与内存预算，建议第一批落地前先做 DataBridge 的接口冻结评审（对齐 v1.0 SemVer 纪律）。
