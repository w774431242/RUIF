## 5. 对外公开发布前的剩余项

**P1（需实机，沙箱无法起游戏进程）**

> **实机进展 · 2026-09-10（用户实测确认）**
> - ✅ **底栏 RUIF 按钮已消失** —— 强证据：证明 v2.0.0 的「移除 `Defs/MainButtons/RUIF_Gallery.xml` + 发布区**镜像清理**」链路在游戏内真正生效（同时也是"删了却还在"这类残留风险的正面反证）。
> - ✅ **`Defs/RUIFSettings.xml` 存在**（随包分发并被游戏加载）。
> - ⏳ **注意证据强度的区别**：文件存在 ≠ 配置被应用器读走。下面第 1/3/4 项仍需证据（`Player.log` 的两行日志 + 设置页显示），届时才能把 GATE-REL 的实机项从 NOT RUN 摘掉。

1. 启用 RUIF 启动 → `Player.log` 出现 `[RUIF] v2.1.1 loaded.` 与 `[RUIF] settings applied: theme=… xmlThemes=… warnings=…`（未找到配置时是 `[RUIF] no RUIF_Settings def -> built-in defaults (theme=vanilla).`）；两行都 `catch` 掉了 —— 若日志里**什么都没有**，先确认是否被 `logOnStartup=false` 关了。
2. ~~确认底栏不再出现 RUIF 按钮~~ → ✅ **2026-09-10 实机确认消失**。
3. 设置页（Mod 设置 → 分类名现为 **`RUIF 框架` / `RUIF Framework`**，随语言变化）：显示版本 / 当前主题 / `XML 配置: …`；点击主题按钮能即时换肤；「打开开发者文档」能拉起浏览器。
4. XML 配置实测：把 `themeId` 改成 `dark`、或取消注释 `themes` 示例 → 重启后主题生效；故意写错颜色名 → 设置页出现告警且不崩。
5. ~~EXC-002 决策~~ → ✅ **v2.1.0 已处置并关闭**（全量 Keyed + 语义解耦，见 §4；方案取舍见 `docs/体检报告_v2.0.0.md` §4.4）。
6. **实机**：组件文案随语言变化（切英文语言看 `DensitySwitch` / `ConfirmDialog` / `ZoomIndicator` 等是否显示英文）；`Player.log` 出现 `[RUIF] v2.1.1 loaded.`。
7. **v2.1.1 新增（缓存失效验证）**：在设置页/组件窗口开着的情况下**切换语言** → 界面文案必须**立即**跟随（验证 `TrCache` 的失效语义）；再切回原语言 → 不得出现旧语言残留。**这是本次缓存改动唯一的实机风险点**（离线单测已覆盖同一语义，见 `Tests/TrCacheTests.cs`）。

9. ⚠️ 简化件收口：`CommandPalette` 全局 Ctrl+K 焦点仲裁 · `MultiLineEditor` 真多行 · `ScrollFadeHint`/`OverflowFade` 真 alpha 遮罩 · `HotkeyBind` 键位捕获。

### 9.1 已知取舍（诚实登记）

1. **切角/圆角是逐行矩形近似**，不含贴图与 9-slice —— 这是"零资产依赖"的代价：极大面板 + 极小切角时边缘可能出现半像素台阶。
2. **动效频率未实机校准**：`MotionSpeed` 默认值（0.08–2.0 周期/秒）为经验值，需实机确认流光/闪烁不刺眼、终端闪烁不引起疲劳。
3. **`DrawDecor` 无测试引用**：纯绘制类离线不可实例化（需 IMGUI 上下文）；其可测部分（相位 / 呼吸 / 闪烁 / 渐层权重 / 周长参数化）已抽到 `ThemeMotion` 并有 6 个用例覆盖，与既有 6 个绘制类的处理策略一致。
4. **12 套配色是经验取值**：单测只保证"16 槽全不透明、底色≠文字、强调色≠底色、招牌装饰特征未丢失"，**不保证观感**；观感验收属实机项。

### 11.6 事故与修复：创意工坊出现重复条目（2026-09-12，用户报）

**现象**：用户报告创意工坊里出现**两个同名的 "RUI Framework"**（封面一新一旧）。

**排查（可复核）**：本地 `Mods\` 只有 1 个 RUIF 文件夹、`ModsConfig.xml` 只有 1 条 `personalchronicle.ruiframework` ⇒ 不是"游戏内两个 Mod"，而是**工坊侧两个条目**。

**根因**：`About\PublishedFileId.txt`（内容 `3800094791`，由游戏在**上传成功后**写入发布区）被 `sync_ruif.ps1` 第 ④ 步**镜像清理**删除 —— 该步规则是"发布区存在、开发区不存在 ⇒ 删"，而开发区天生没有这个文件。ID 丢失后，下一次上传被 Steam 视为新作品，于是另建条目。

**修复**：
1. `sync_ruif.ps1`：`Keep = @('About\PublishedFileId.txt')` —— 镜像清理放过；并在结尾**回写开发区**（`[BACKFILL]`）。
2. `verify_release.ps1`：镜像检查放过该文件 + 新增断言 **「工坊条目 ID 受保护（两区存在且一致）」**，缺失即 FAIL。
3. 已把 `3800094791` 回写开发区；门禁复跑 **GATE PASS**（第 6 道三条全 PASS：无垃圾 21 文件 / 镜像一致 / 工坊条目 ID 受保护）。

**遗留（需人工在 Steam 侧处理）**：工坊上仍有两个条目，**必须保留一个**（建议保留有订阅/收藏数据的那个），删掉另一个；若最终保留的是**旧条目**，需把旧 ID 写回 `About\PublishedFileId.txt`（两区同改），并复跑门禁。

**教训**：镜像清理的"开发区的真源"假设**不适用于外部程序写入的文件**。凡是「由游戏 / 平台写入发布区」的文件（`PublishedFileId.txt`、以及将来可能出现的其他元数据）都必须进白名单，且**门禁要断言其存在**，否则这类丢失会一路静默到用户在工坊侧发现。
