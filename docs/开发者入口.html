一 · 这是什么（30 秒）

RUIF 是一个 UI 框架 Mod（和 Harmony / HugsLib 同类的"框架型 Mod"）：提供无状态的绘制组件、设计令牌、布局助手，让 Mod 作者不用再手算 Rect、不用再配 GUI.color。

你要做的说明
让玩家订阅 RUIF全游戏只加载一份 RUIF.dll，从根上避免"多个 Mod 各带一份不同版本 dll"的经典冲突
自己的包里不要带 RUIF.dllcsproj 里 <Private>false</Private>。发布包里出现 RUIF.dll 就是错
声明依赖方式见 §二。这一步选错，后面全是坑
自己画界面框架没有演示区、没有画廊、没有预设页面 —— 它只提供能力（组件 / 令牌 / 布局 / XML 配置）
关键认知：RUIF 的组件是无状态静态方法——没有实例、没有控件树、没有 ViewModel。你每帧调用一次，当帧就画完；数据由你准备并传进来。所以"学 RUIF" ≈ 学它的令牌名与常用组件签名，不需要学新范式。

二 · 第一步：选依赖模式（二选一，混用即"假降级"）

模式About.xml探测方式适合
硬依赖
（推荐）		modDependencies + loadAfter直接调 RUIF.Api.IsAvailable(minVersion)，只做版本门控没有框架就没意义的功能
软依赖不写 modDependencies，只写 loadAfter反射扫 AppDomain 找 RUIF.Api；所有 RUIF 调用隔离到独立类型，方法标 [MethodImpl(NoInlining)]有原生兜底路径的功能
为什么不能"声明硬依赖 + 又写 else 降级"：RUIF.Api 类型本身就在 RUIF.dll 里。框架缺失时，任何会被 JIT 的代码路径出现 Api.Xxx，就会在方法编译阶段抛 FileNotFoundException / TypeLoadException——try/catch 拦不住，你的 else 分支永远不会执行。

三 · 5 分钟上手（抄模板最快）

① About.xml（硬依赖写法）

<modDependencies>
  <li>
    <packageId>PersonalChronicle.RUIFramework</packageId>
    <displayName>RUI Framework</displayName>
  </li>
</modDependencies>
<loadAfter>
  <li>PersonalChronicle.RUIFramework</li>
</loadAfter>

② csproj 引用（不随包分发）

<Reference Include="RUIF">
  <HintPath>路径/RUIF/Assemblies/RUIF.dll</HintPath>
  <Private>false</Private>
</Reference>

③ 最小消费示例（直接抄）

框架包内不再附带可编译的模板工程（旧 _Template/ / Sample/ 已随换肤层一并移除）。一个硬依赖消费者的最小写法如下（v1.0.1 源码工程内编译通过）：

// 你的 Mod 主类（硬依赖模式：直接 using RUIF）
using RUIF;
using UnityEngine;
using Verse;

public class Dialog_MyWindow : Window
{
    public override void DoWindowContents(Rect inRect)
    {
        var  col  = Layout.Column(inRect, Tokens.SpaceSm);   // 布局游标
        Rect head = col.Take(30f);                       // 取一段（超界自动裁剪）
        Draw.Label(head, "我的界面", Tokens.FontBody, Tokens.Text, TextAnchor.MiddleLeft);
        if (Widgets.ButtonText(col.Take(28f), "确定")) Close();   // 简单按钮用原版 Widgets（RUIF 无通用按钮）
    }
}
要点说明
调用约定组件是 静态类.方法(rect, ...)，无实例、无控件树；交互件返回 bool（true＝本帧被激活）
取色一律用 RUIF.Tokens.* 只读令牌；禁 new Color / 裸改 GUI.color（会染色泄漏）
软依赖若走软依赖，须把 RUIF 调用隔离进独立类型并标 [MethodImpl(NoInlining)]（见 §二、§七）

④ 看效果

  • 跑起来看：编译你的 Mod → 启用 RUIF 与本 Mod → 打开自己的窗口（示例是 Mod 设置页的按钮）。框架不会给你任何现成界面，看到的就是你自己画的。
  • 离线看组件长相：终极宝典v1.0-fixed.html（离线全量组件卡 + 实例与布局配方）；手把手从零开始见 零基础上手教程.html（30 分钟，示例真编译）。

四 · 配置（无需配置）

框架没有任何 XML 配置入口：不定义设置 Def、不读写配置文件、不注册底栏按钮。所有外观参数由只读设计令牌 RUIF.Tokens 提供，直接取用即可。想自定义配色，请在你的 Mod 内自行持有颜色常量——框架只供给组件，不承担换肤引擎。

与旧版的差异：v1.0 公开发布前，框架曾提供 RUIFSettings.xml（themeId / themes / 16 色覆盖）的换肤机制，现已整体移除。对应的 Theme.* 令牌一律更名为 Tokens.*（语义不变，取值即原暗色基线）；Theme.Apply / Register / ActiveId 已删除、无替代。

六 · 怎么查 API（三条路，任选）

  1. API参考.md：按类型分组，列出全部公开成员的真实签名。类型名规则：RUIF.* 用短名，引擎类型用全限定名（UnityEngine.Rect / Verse.GameFont）。
  2. IDE 悬停：引用 dll → RUIF.xml 提供成员级中文注释（含设计约束与"为什么"）。
  3. 示例源码：见 §三③ 的最小消费示例（可直接编译的模板工程已随换肤层移除）。
三个高频入口（记住这三个就够起步）： 
var col = RUIF.Layout.Column(rect, RUIF.Tokens.SpaceSm);  // 布局：拿游标
Rect r    = col.Take(30f);                              // 取一段（超界自动裁剪）
RUIF.Draw.Label(r, text, RUIF.Tokens.FontBody, RUIF.Tokens.Text, TextAnchor.MiddleLeft);  // 画
颜色一律取自 RUIF.Tokens.*；要加边框/底色用 RUIF.Draw.Box / RUIF.Draw.Border / RUIF.Atoms.SectionFrame； 想直接拿现成小部件就用 PanelAtoms.StatRow / ProgressAtoms.CapacityBar / StatusAtoms.PulseDot 这类静态组件。

七 · 六个常见坑（都踩过，按频率排序）

坑表现 / 正确做法
软依赖却不隔离调用主路径出现 RUIF.xxx → 框架缺失时整个方法 JIT 失败。
做法：探测用反射，调用进独立类型，方法标 [MethodImpl(NoInlining)]（否则 JIT 内联会把依赖泄回调用方）
把令牌当"可换肤"用RUIF.Tokens 是只读固定值，框架不提供运行时换肤 / 主题注册。做法：需要多套配色就在你自己的 Mod 里持有颜色常量并自行切换，不要期待改框架令牌（旧换肤层已于 v1.0.0 前移除）
发布包内嵌了 RUIF.dll多份副本冲突、版本错乱。做法：csproj Private=false，发版前打开自己包的 Assemblies/ 看一眼
自己 new Color / 裸改 GUI.color颜色绕过设计令牌，还会染色泄漏到全游戏。做法：一律走 RUIF.Tokens 令牌；必须临时改绘制态时用 using (RUIF.Draw.Color(...)) 作用域
类里定义了名为 Draw 的方法类内写 Draw.Box(...) 会被同名成员遮蔽（CS0119）。做法：写全限定 RUIF.Draw.Box(...)
在绘制里分配内存每帧 new List / LINQ / 闭包 → GC 卡顿。做法：缓冲与布局计划缓存到字段，绘制时零分配

八 · 版本与承诺

  • 当前版本：v1.0.1（2026-09-12）—— 回归纯组件库（移除主题 / 换肤层）+ 开发者包精简；无公共 API 新增，公共 API 面与 v1.0.0 一致（73 类型 / 435 成员）。
  • SemVer：公共 API 变更遵循语义化版本。v1.0.0 为首次公开发布（内部迭代线 v2.0.0–v2.2.1 的成果即本次内容，其中 v2.0.0 完成了公开前的 API 收敛）。自 v1.0.0 起对外承诺：删除/修改公共 API 前先标 [Obsolete] 并保留一个主版本。
  • 版本门控：RUIF.Api.IsAvailable("1.0")。版本号在类型初始化时即可用，不依赖框架 Mod 的构造时序。
  • 框架不带 UI：不内置演示界面、不注册底栏按钮、不写存档、组件无持久状态、不引 Harmony —— 与其它 Mod 的冲突面被压到最小。
  • 不含换肤引擎：框架只供给组件与只读令牌，不做主题注册 / 运行时换肤 / XML 配色覆盖（旧换肤层已于 v1.0.0 公开发布前整体移除）。
  • 报问题：附 Player.log（%USERPROFILE%\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Player.log）并搜索 [RUIF] 关键字。
文档诚实口径：凡标 ⚠️ 有代价 的能力（圆角/自定义字体/图标）都不会被写成 ✅；标 ❌ 不承诺 的（保留模式自动 diff、实时模糊、多线程 UI、松散 TTF）不会偷偷实现成半成品。文档示例必须编译通过才写入。
