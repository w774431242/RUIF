## 1. 执行摘要

**总判定：公开发布 BLOCKED；对单一消费者（Personal Chronicle）有条件可内测。**

框架的**工程内核是健康的**——编译 0 错 0 警、单测 197/197、分层零反向依赖、不引 Harmony、无存档面、本地化键工程干净。问题集中在**三个非编码层面**：

1. **对外陈述与实际不符**（诚信级）：`About.xml` / `README` / 随包 `DevDocs` 声称的「源码零硬编码」「绘制路径零堆分配」「113 类型 / 603 成员」「153 件组件」，**四项全部被实测证伪**。
2. **交付物不内聚**：发布区 `RUIF.xml` / `RUIF.pdb` 是 09-13 的旧构建产物（dll 是 09-15 的），第三方拿到的 IntelliSense 文档与真实 dll 不符。
3. **门禁不具备强制力**：九道发布门禁中**没有硬编码检查项**；唯一的体检脚本命中 24 处却**退出码恒 0**、不阻断。宣称因此长期失守而无任何机制报警。

另有一项**引擎机制层面的 P0**：框架把 `GameFont.Tiny` 的行高当作常量 18px，而原版引擎在特定条件下会把 `Tiny` **静默降级为 `Small`（22px）**，导致 v1.1.2 刚修复的 `Industrial.Gauge` 标题压弧缺陷在部分机器上回归。

## 4. 分维度发现

### 4.1 架构（PASS WITH EXCEPTION，局部 BLOCKED）

- **分层与依赖方向 PASS**：以 Layout+Components 全部类型名整词扫描 `Source/Core/`，命中仅 3 处且全在 XML 文档注释内；`Core` 对上层**零代码级依赖**，无循环。
- **引用面 PASS**：PE `AssemblyReferences` 实测 `mscorlib` / `UnityEngine.CoreModule` / `Assembly-CSharp` / `UnityEngine.TextRenderingModule` / `System.Core` / `UnityEngine.IMGUIModule`，为白名单子集。
- **BLOCKED 1 — 例外登记失效（违反 GOV-012）**：`EXC-003` 的登记主体 `RUIFSettings.Warnings` / `ValidNames()` / `SourceSummary()` **已随配置系统删除**（`grep` 零命中），例外成立基础消失却仍标「登记中」，且同一文档另一处又写「已自然失效」，**自相矛盾**。同时，**主题层公共 API 的无 `[Obsolete]` 删除未登记任何例外**——`README.md:103` 自述其为 SemVer 例外，但例外表只有 EXC-001/002/003，无对应条目。
- **BLOCKED 2 — 定位红线冲突**：`PawnTableAtoms.cs:110` 读 `Find.CurrentMap`；`InputPlusAtoms.cs:262`、`NavAtoms.cs:118`、`NavAtomsB.cs:183` 调用 `Find.WindowStack.Add(new FloatMenu(...))`——与 `README.md:98-99`「框架不带 UI、不画窗口」「组件内禁读游戏状态」**直接冲突**。
- **静态可变状态 2 处**（P2）：`NavAtoms.cs:123 pendingMorePick`（**跨帧**存活，同帧两个 TabBar 实例会串台，严重度高于另一处）、`NavAtoms.cs:217 clicked`（单帧中转，不可重入）。

### 4.2 机制与 API 事实（多项 P0/P1）

- **原版 API 事实 PASS**：对源码抽取 458 个 `类型.成员` 引用（剔除自有 207 条），对游戏程序集逐条核验，**无一条解析失败**，无过时 API。反编译确认 `Translator.Translate(this string, params object[])` 确带 `[Obsolete]`，与框架改用 `NamedArgument` 的论断一致。
- **RW 1.6 三条硬约束均已内建 PASS**，但 README 措辞不准（见 §6）。
- **P0 — Tiny 静默降级导致高度预算失准**：`Tokens.FontLabel => GameFont.Tiny`，而原版 `Verse.Text.Font` 的 setter 在 `!Text.TinyFontSupported`（触发条件含玩家可开的 `Prefs.DisableTinyText`、`Steam.Deck.IsSteamDeck`）时把 `Tiny` **静默降级为 `Small`（行高 22px）**。`Measure.RowHeight` 却把 Tiny 写死 18f：

  ```csharp
  // Source/Core/Measure.cs:29-31
  case GameFont.Tiny:   return 18f;   // 手写魔数，未取自引擎
  case GameFont.Medium: return 30f;   // 手写魔数
  default:              return 22f;   // = Text.SmallFontHeight
  ```

  该文件开篇（`:9-12`）恰好批评「行高靠手写魔数」，而它自己只有 `default` 档取自引擎常量。后果：`Industrial.Gauge` 的 `GaugeLabelBand = 15f` 与 14px 标题带的几何推导在降级机器上失效，**v1.1.2 刚修复的「标题压弧」回归**。凡以 `Tokens.FontLabel` 推算高度的组件同源受影响。
- **P1 — 绘制路径分配**：实测命中 12 组，真违规包括 `ChartCandAtoms.cs:224-227,267-270` 共 8 处 `Array.ConvertAll` + 闭包、`Industrial.cs:313/243` 每帧 `ToString`、`InputPlusAtoms.cs:383-393` 每帧 `SplitLines`、`InputCandAtoms.cs:50`。**注**：质量与发布部指出机制部清单中 `new Vector2/new Rect`（值类型构造）**不产生堆分配**，属高估，已在本报告修正。
- **P1 — `Widgets.DrawLine` 双标**：`Charts` 已弃用改用 `TexFmt.Line` 烘焙，但 `ChartCandAtoms.cs:59/65/76/130`、`NavAtomsB.cs:61-62`、`DomainCandAtoms.cs:95/126` 共 8 处仍在用。若 v1.1.1 的根因叙事为真，这 8 处在滚动视图内同样存在错位风险；若为假，则 Gauge 改烘焙的设计前提需重述。**二者必有一错**。
- **P1 — 简化件免责不随包**：`CommandPalette` / `MultiLineEditor` / `ScrollFadeHint` / `OverflowFade` / `HotkeyBind` 五件均为部分实现，免责仅写在 **README（不随包分发）**，`About.xml` 完全未提。
- **两处注释与程序集不符**：`Measure.Clamp` 称 `GenText.Truncate`「原版自带缓存参数」（实参未传 ⇒ 零缓存）；`Measure.Width` 依赖的 `GenUI.GetWidthCached` 缓存键**只有 string 不含字体** ⇒ 跨字号复用同一文案会取到错值。

### 4.3 数据与存档（PASS WITH EXCEPTION / N/A）

- **承诺成立**：源码与发布区 dll **双重零命中** 存档相关符号。设置系统（`RUIFSettings`）系**有据移除**（CHANGELOG 与 docs 均有记录），**对既有存档零影响**——它是 Def 非 ModSettings、经 XML 直读不走 Scribe、且非可被存档引用的 Def 类型，故无迁移负担。
- `TrCache` 容量 512 **真实强制**，但超限策略是**全清重建（非 LRU）**；失效依据是 `LanguageDatabase.activeLanguage` 的**引用相等**，且**缓存键不含语言维度** ⇒ 正确性 100% 依赖「切语言时引用会变」这一前提（**尚未核实，见 §8 未决项**）。失效计数器为 `internal`，生产无日志 ⇒ 最危险的「该失效却永不失效」**无自检**。
- `TexCache` 上限 128（**按条目数而非字节数**）；`FoldColor` 存在静默有损折叠（不同色值可折到同一键 ⇒ 贴图串色）；`Charts.cs:391-392` 的注释与 `TexCache.cs:151-152` **直接矛盾**。
